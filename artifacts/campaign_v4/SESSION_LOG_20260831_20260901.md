## 13. Why integer-ID LEGR was near chance (user: “why is the LEGR accuracy so low”)

Diagnosis, then confirmed by wiring work:

1. `encoders_v2.py` (`LEGRDualEncoderV2`: MiniLM tool-name nodes + directed GNN) **existed but was never called** from `train.py` / `run_campaign_v4.py`.
2. “Directed” campaign runs were still **integer `nn.Embedding` + directed GNN**.
3. Mean-pool over OOD diamond / fork-join twins collapses graphs that share tools.
4. Query tower is pretrained MiniLM; graph tower is random IDs. They do not meet in the same space.
5. More epochs made **legacy worse** (75ep R@1 0.003), not better. This was not an under-training problem.

User asked how to fix it. Agreed fix: actually train V2 as `graph_encoder_type=directed_text` / run name `legr_directed_toolname_*`, **new directories only**.

- `resolve_graph_encoder_settings` maps `directed_text` / `legr_directed_toolname`.
- `train.py` / `eval.py` instantiate `LEGRDualEncoderV2` and precompute tool-name features from `TOOL_VOCAB`.
- Campaign runner gained architecture `directed_text` with labels `legr_directed_toolname_{no_ged,ged}_{tier}t`.
- Integer IDs from `dag_to_pyg` are looked up to tool names then MiniLM.

## 16. Tool F1 discussion and SetGNN tied MiniLM (user: “make this change”)

User asked how to raise tool F1, then asked to implement the split-readout + tied MiniLM change, and not to kill the running fair eval.

**Why extra GNN layers / GED would not move tool F1 much**

Tool F1 is computed from the **top-1 retrieved DAG’s tool set** vs gold. Toolname was F1 0.82 / R@1 0.62 vs SBERT-FT 0.98 / 0.93. Mean-pool after the GNN mixes tool identities. GED vs no-GED was 0.82 vs 0.81 on toolname.

**What was implemented (`LEGRDualEncoderV3`, type `setgnn_tied`)**

- One MiniLM shared by query tower and tool-name nodes (no second frozen copy; state dict has a single `text_encoder.backbone`).
- Node-set attention pool over MiniLM node features (tools).
- Directed GNN pooled hidden **without** the old projection, concatenated with the set vector, then a fuse layer to 256-d, L2-normalized.

## 21. How to explain LEGR over SBERT (paper framing)

Recorded 1 September 2026 after the twin-gallery numbers. This is the agreed claim structure. It is **not** a claim that LEGR already beats SBERT-FT on overall R@1.

**You cannot claim “LEGR is better than SBERT” on the numbers in this log.** You can claim that **SBERT’s win is the wrong task**, and that **LEGR is the architecture that can do the right one**.

The paper task is not “match the tools.” It is: same tools, different execution graph (diamond vs fork-join with identical nodes). A text encoder that sees a tool bag or a serialized `A→B` string is built for token sequences, not for directed structure.

### What the two galleries measure

| Gallery | What it tests | Who wins (15-tool, this session) |
|---|---|---|
| 50 unique DAGs, 50 unique toolsets, **0 twins** | Tool-bag retrieval | SBERT-FT R@1 **0.93**, SetGNN **0.83**, toolname **0.62**, frozen SBERT **0.43** |
| 322 DAGs = test ∪ corpus, **twins present** | Structure among same tools | SBERT-FT tools-only **0.65** and **flat** (R@1≈R@5). SBERT-FT `dag_text` **0.21**. Toolname GNN **0.20 / 0.50** (R@1 / R@5). Frozen `dag_text` **0.02**. Frozen tools-only **0.29** (also flat). |

On the 50-DAG set, SBERT-FT is doing `query → tool names`. Frozen `dag_text` vs tools-only on that gallery was ~0.37 vs 0.38: edges in the string did almost nothing because no two candidates shared a toolset.

On the 322-DAG set, tools-only **cannot break ties among twins** (R@1 stuck to R@5). Writing the graph as a sentence does not fix that: fine-tuned `dag_text` R@1 is **0.21**. That number belongs in the paper as “serialization is not a GNN.”

### What to write (without lying)

1. Fine-tuned SBERT is the right baseline for **language**. It should win when the gallery is one DAG per toolset. Report 0.93. Do not hide it.
2. That number is **not** structural generalization. Put gallery composition in the table caption: unique toolsets vs twin density.
3. LEGR’s inductive bias is directed message passing over tool-name nodes: the readout can differ for `A→B` vs `B→A` with the same node set. SBERT’s inductive bias is a single vector over a token sequence. That is why twins were built.
4. Evidence this session **does** have: integer-ID LEGR was a broken control (R@1 0.08 directed / 0.003 legacy at 75 epochs), not a GNN failure. Tool-name nodes beat frozen SBERT on the 50-DAG gallery (0.62 vs 0.43). Set pool recovered tools (F1 0.95 vs toolname 0.82). GPT-OSS v3 is a strong *generative* baseline (F1 ~0.95, EM 76–80%), a different problem than retrieval.
5. Evidence this session **does not** have: LEGR beating SBERT-FT on overall 322-DAG R@1. Toolname and SetGNN are both ~0.21, matching SBERT-FT `dag_text` 0.21. Same-toolset R@1 is only slightly above chance (0.24–0.27 vs 0.15). Do not claim a twin-ranker win yet. The tools-only 0.65 is not a counterexample; it is a gallery-order tie (see §23).

### Defensible sentence

Fine-tuned SBERT is a strong tool-set retriever. When every candidate has a unique toolset it reaches R@1 0.93; when structural twins are in the gallery, tools-only embeddings of twins are identical (cosine 0.9998) and reversed-edge ranking is chance. LEGR is the model class that can represent those twins as different vectors. We do not claim it already wins that ranking.

### Missing table that would actually support “LEGR over SBERT”

Same-toolset R@1 substantially above chance **and** above SBERT `dag_text` (currently 0.23). Twin hard-negatives in the loss are the next training change. Until that number moves, the paper should argue **protocol and inductive bias**, not overall SOTA. See §23 for the proof that SBERT cannot use edges.

## 23. Proof: SBERT-FT is edge-blind (1 September 2026 07:15)

Script: `scripts/prove_sbert_text_only.py`. Output: `artifacts/campaign_v4/results/sbert_text_only_proof_15t.json`. Checkpoints: `sbert_ft_ged_15t_s42`, `legr_directed_toolname_ged_15t_s42`, `legr_setgnn_tied_no_ged_15t_s42`.

Setup: 15-tool held-out, **300 queries**, **322-DAG gallery** (test unique ∪ corpus unique), **927 twin pairs**, **49 toolsets with twins**. Every query’s gold DAG has at least one twin. Chance same-toolset R@1 = mean `1 / |same-toolset pool|` = **0.1538**.

### 23.1 Twins collapse in SBERT embedding space

Mean pairwise cosine. Different-toolset pairs sampled with seed 42.

| Encoder | Twin cosine | Diff-toolset cosine | Twin pairs with cos > 0.99 |
|---------|-------------|---------------------|------------------------------|
| SBERT-FT tools-only | **0.9998** | 0.1873 | **1.000** |
| SBERT-FT dag_text | 0.9463 | 0.1833 | 0.0367 |
| SBERT-FT reversed-edge text | 0.9432 | — | — |
| LEGR toolname + GED | **0.4317** | 0.1787 | — |
| LEGR SetGNN no GED | **0.6256** | 0.2249 | — |

Tools-only twins are the same vector. Serialized `dag_text` still collapses twins to 0.95. LEGR produces distinct twin embeddings.

### 23.2 Reverse every edge → SBERT ranking at chance

Same-toolset R@1 = gold ranked only against gallery DAGs that share its tools. If the encoder uses direction, flipping `A -> B` to `B -> A` should collapse this.

| Condition | Same-toolset R@1 | Full-gallery R@1 | R@3 | R@5 |
|-----------|------------------|------------------|-----|-----|
| SBERT-FT dag_text | 0.2333 | 0.2133 | 0.6100 | 0.8533 |
| SBERT-FT tools-only | 0.6900 | 0.6467 | 0.6500 | 0.6567 |
| SBERT-FT reversed-edge text | **0.1700** | **0.1500** | 0.5967 | 0.8667 |
| Chance | **0.1538** | — | — | — |
| LEGR toolname + GED | 0.2733 | 0.2000 | 0.4000 | 0.5033 |
| LEGR SetGNN no GED | 0.2367 | 0.2100 | 0.5667 | 0.8133 |

Reversing edges drops SBERT same-toolset R@1 to chance. R@5 stays ~0.87: the model still finds the tool bag, not the DAG. Tools-only R@1 ≈ R@5 because twins cannot be broken in embedding space.

### 23.3 The 0.65 tools-only R@1 is gallery order, not ranking

Gallery construction concatenates **test unique first**, then corpus unique. **0.98** of gold DAGs have the lowest gallery index among their twins. `argmax` on a numerical tie returns that first index, so gold “wins.”

Tools-only same-toolset R@1 under explicit tie-breaks:

| Tie-break | Same-toolset R@1 |
|-----------|------------------|
| Pick lowest gallery index (matches default argmax) | **0.9733** |
| Pick highest gallery index | **0.0000** |
| Pick random tied twin | **0.1467** ≈ chance |

Flip the tie-break and the tools-only “win” disappears. Do not report 0.65 as structure.

### 23.4 Why LEGR is better **in this scenario** (not overall SOTA)

The paper task, and the product task, is: **same tools, different execution graph**. Diamond vs fork-join with identical nodes. Wrong edges are a wrong plan (order, parallelism, dataflow) even when tool F1 is high. A retriever that cannot tell twins apart cannot be the router.

SBERT is better when the gallery has one DAG per toolset (50-DAG protocol, R@1 0.93). That is a different problem: `query → tool names`. It is not this problem.

On this problem LEGR is the better **model class** for three measured reasons:

1. **Representation.** Directed message passing over tool-name nodes can emit different vectors for `A→B` vs `B→A`. SBERT tools-only cannot: cosine **0.9998**, 100% of twin pairs above 0.99. SBERT `dag_text` still sits at 0.95. LEGR twin cosine is **0.43** (toolname) and **0.63** (SetGNN). Only LEGR actually embeds the graph.
2. **Direction.** Reverse every edge and SBERT same-toolset R@1 falls to **chance (0.17)**. The GNN is the architecture whose readout is allowed to change under that intervention. Serialization of `A→B` as a sentence does not substitute for a GNN.
3. **Honest ranking.** After removing the argmax-on-tie artifact, SBERT tools-only cannot rank twins at all (random tie → 0.15). LEGR same-toolset R@1 is **0.24–0.27**, above chance, because the embeddings differ. That is a small lift, not a headline win, but it is the only number in this log that is even *about* structure.

What this does **not** license: “LEGR beats SBERT” on overall 322-DAG R@1. Both sit at ~0.21. Same-toolset R@1 is not yet a large gap over SBERT `dag_text` (0.23). Next training change is twin hard-negatives in the loss, not more GNN layers or GED λ.

**Paper sentence for this section:** SBERT-FT is a tool-bag retriever. When twins share a toolset its embeddings coincide and reversing edges does not change ranking beyond chance. LEGR is better for structural routing because it is the encoder that represents those twins as different graphs, which is the condition under which a router can prefer a safe plan over an unsafe one with the same tools.
